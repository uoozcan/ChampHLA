## Scientific Benchmark Policy

All scientific summaries must use only 1000 Genomes samples that satisfy all of the following:
- public HLA ground truth from the Gourraud et al. dataset
- matched `wgs`, `wes`, and `rnaseq` availability
- truth-supported benchmark loci only

Current headline truth-supported loci:
- `A`
- `B`
- `C`

Detailed tool result files may still contain additional loci, but they are outside the current headline benchmark scope.

Primary endpoint:
- exact two-field allele-pair match

Secondary endpoint:
- exact three-field allele-pair match where derivable and comparable

## Interpretation Guidance

When a refreshed real 1000 Genomes run is available, the main interpretation order should be:
1. cohort assembly and tri-modal filtering
2. single-tool performance by modality and gene
3. majority vote versus weighted consensus on holdout
4. calibration and confidence-stratified error analysis
5. ambiguity-aware evaluation at 2-field and 3-field
6. abstention behavior
7. discordance patterns across DNA and RNA modalities

## Phase-Gated Reporting Policy

If a tool fails in a modality during the current refresh:
- report it explicitly as `unavailable` in metadata and coverage summaries,
- exclude it from method-comparison numerators for that modality,
- preserve already completed modalities for that tool when valid,
- do not convert engineering failure into a biological performance claim,
- keep headline narrative focused on the valid truth-backed comparison set.

This policy is especially important while the Puhti execution layer is still being hardened for storage-heavy WES and RNA runs.

## Notes

The fixture-based development benchmark remains useful for:
- regression testing benchmark tables
- parser validation
- confidence and consensus plumbing checks

It should not be cited as a real cohort analysis in scientific text.
